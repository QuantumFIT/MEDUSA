MEDUSA, running in your browser

MEDUSA keeps a quantum state as a multi-terminal binary decision diagram and, for circuits with loops, computes a symbolic summary of the loop body once instead of executing every iteration. Every number on this page is measured live on your device by the simulator's own C code compiled to WebAssembly.

What the summary does

  1. Abstract. Each distinct amplitude in the state entering the loop is replaced by a symbolic variable. Grover's state has only a handful.
  2. Run the body symbolically. The gates are applied once, and the leaves of the MTBDD become terms over those variables.
  3. Refine to a fixpoint. If two basis states sharing a variable are updated differently, the variable is split and the body is run again.
  4. Evaluate. The resulting update map is applied for all K iterations on a few numbers, with no further gate operations.

Loop-free circuits: the simulator itself is fast

These circuits from the repository's benchmark set have no loops, so summarization plays no part. Gates are applied directly on the decision diagram, whose size follows the structure of the state and not 2n.

About this build. MEDUSA with the MoToBuddy backend, compiled with wasi-sdk 25 (clang, -O2) to a WASI command module. Each run starts a fresh instance in a Web Worker, exactly like a fresh process, and nothing leaves your device. Times are the simulator's own --info timing. The browser build differs from a native one in three ways: the float backend uses 64-bit leaves where the native default is __float128; the exact algebraic backend links GMP's mini-gmp instead of full GMP, so its big-integer arithmetic is slower than native; and there is no link-time optimization. Native runs are faster.
